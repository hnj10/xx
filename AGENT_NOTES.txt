## 三个致命坑（务必记住）
============================================================

### 坑 1：SERVER__PORT 环境变量劫持后端端口 【每次必踩，最高频】
- 沙箱/WorkBuddy 每次启动会注入：
      SERVER__PORT=<随机端口>
      SERVER__HOST=127.0.0.1
  实测出现过 61437、64359 —— **值每次开机都变，不要写死，清空即可**。
- Spring Boot 宽松绑定把 SERVER__PORT（双下划线）解析为 server.port，
  优先级高于 application-dev.properties 里的 8081。
- 症状：后端日志
      Tomcat initialized with port 6xxxx (http)
      Web server failed to start. Port 6xxxx was already in use.
  注意：占用 6xxxx 的是 WorkBuddy.exe 自己，不是 Java 进程（别去杀 Java，找不到）。
- 解决（必须）：启动后端前清空这两个变量
      set "SERVER__PORT="
      set "SERVER__HOST="
  start-backend.bat / start-all.bat 已做。
- 已验证无效的做法：`-Dserver.port=8081` 压不住 env 变量（实测仍绑 6xxxx）。
  正确组合 = 清空 env + `-Dspring-boot.run.arguments=--server.port=8081` 双保险。

### 坑 2：Maven 不可用（两个陷阱，都要避开）
- (a) 项目自带 mvnw 损坏：.m2\wrapper 下的分发不完整，
      报 ClassNotFoundException: org.codehaus.plexus.classworlds.launcher.Launcher
      → 不要用 mvnw；也不要用 Git Bash 的 bash mvn（同样报错）。
- (b) 项目内 apache-maven-3.9.9 也是坏的：boot\ 与 lib\ 只有 *.license，无 jar
      → mvn.cmd 文件存在但一跑就报同样的 classworlds 错。
      → 判断真假 Maven 要看 `boot\plexus-classworlds-*.jar` 是否存在，不能只看 mvn.cmd。
- 解决：用 IntelliJ 自带的完整 Maven（已验证可用）
      D:\IntelliJ IDEA 2024.3.2.2\plugins\maven\lib\maven3\bin\mvn.cmd
  脚本会依次尝试：MAVEN_HOME -> 项目内(带 jar 校验) -> IntelliJ -> PATH，取第一个真可用的。
- Git Bash 里调 Maven 的两个注意：
  * JAVA_HOME 必须是 Windows 反斜杠格式：C:\Program Files\Zulu\zulu-21
    （用正斜杠会报 "JAVA_HOME is not defined correctly"）
  * 直接调用 .cmd 文件即可；不要用 cmd //c（被安全策略拦截，引号也难处理）
- 本机 JDK：C:\Program Files\Zulu\zulu-21（Java 21，满足 Boot3 的 17+）

### 坑 3：MySQL 需初始化（脚本已幂等处理）
- 首次执行 springBootTest\sql\genshin_db.sql 建库建表灌数据（表存在则跳过）
- mysql.exe：C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe
- 若 MySQL 没启动，后端会连不上库，先确认 3306 在监听。

## 标准启动流程（重置后）
============================================================
1. 双击 start-all.bat
   - 会：清端口劫持变量 -> 初始化DB -> 找真 Maven + JDK -> 新开两窗口启动前后端
   - 首次较慢（npm install + mvn 编译），约 30-90 秒
2. 验证（任选其一）：
   - netstat -ano | findstr ":8081 :5173"  看是否 LISTENING
   - curl -s http://192.168.68.4:8081/api/user/list
   - curl -s -X POST http://192.168.68.4:5173/api/user/login ^
       -H "Content-Type: application/json" ^
       -d "{\"username\":\"traveler\",\"password\":\"123456\"}"
     走前端代理，返回「登录成功」说明整条链路通。
3. 停止：双击 stop-all.bat

## AI 须知：若不用脚本、手动启动
============================================================
- 后台进程**不要**用 `nohup ... &`：进程会随 shell 退出被回收（假启动）。
  正确做法：用工具的 run_in_background 直接托管长跑命令（不加 & / nohup）。
- 手动后端命令：
      unset SERVER__PORT SERVER__HOST
      export JAVA_HOME='C:\Program Files\Zulu\zulu-21'
      cd springBootTest
      "<IntelliJ maven 路径>\mvn.cmd" -DskipTests ^
        -Dspring-boot.run.arguments=--server.port=8081 spring-boot:run
- 手动前端命令：
      cd genshin-login-vue && npm install && npm run dev

## 其他注意
- wmic.exe 被安全黑名单拦截；查进程用 tasklist /fi "PID eq X"
- 前端 vite.config.js 的 /api 代理不改写路径，后端 context-path=/api，两边刚好对上，不要改
- .m2 依赖缓存一般在，编译不会太慢；若每次都重下依赖，说明 .m2 也被清了（正常）
- 后端 mybatis-plus.mapper-locations 指向 classpath*:/mapper/**/*.xml，但项目无 mapper xml
  （用的是 BaseMapper 通用方法），属正常，不是缺失。
